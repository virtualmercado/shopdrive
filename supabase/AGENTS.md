- Plan contracts: versions in plan_contract_versions (immutable once published, SHA-256 by trigger), pointer in plan_contract_settings, immutable plan_contract_acceptances written only by service-role RPC record_plan_contract_acceptance via edge function accept-plan-contract. Why: legal evidence must never be rewritten; acceptance never activates a plan.
- Minha Rede: toda métrica sai de `compute_brand_network_metrics` (cliques = template_click_events.counted, ativações = profiles.source_template_id válidos, operacional = `_bn_store_facts`); cliente só via `get_my_brand_network_*` (owner+primary+MARCA direto+flag), admin via `admin_get_brand_network_*`. Why: fórmula única, sem secondary atravessar.
- Jobs internos autenticam por `x-internal-job-token` via `verify_internal_job_token` (token em `internal_job_tokens`); relatório MARCA envia só após `claim_brand_network_report_send` e nunca reenvia `delivery_unknown`. Why: SMTP sem idempotência.
- MARCA upgrade: empresa só via `prepare_my_marca_brand_account`, contrato só via `get_current_marca_contract`; troca PRO/PREMIUM→MARCA em `marca_scheduled_upgrades` (só PIX/anual, effective_at = current_period_end, ativa só via `activate_marca_scheduled_upgrade` com pagamento 'paid' de valor congelado). Why: sem cobrança dupla nem perda do período pago.
- Fila de e-mail: o worker só pega itens via `claim_email_queue_batch` (FOR UPDATE SKIP LOCKED, prioridade desc + criação; relatório MARCA mantém claim próprio); `category` marketing nunca recebe BCC do suporte; lock expirado após `send_started_at` vira falha `delivery_unknown`, nunca reenvio. Why: dois workers enviavam o mesmo item e campanhas não podem atrasar transacionais.
- Marketing suppression: `email_suppressions` (normalized lower/trim email, unique) is consulted ONLY for `category='marketing'` — in `enqueue_marketing_email`, on unsubscribe (pending marketing → `suppressed`) and in `process-email-queue` right before SMTP (fail-closed). Unsubscribe tokens are opaque, stored as SHA-256 hash in `email_unsubscribe_tokens`; public page `/descadastro?token=` uses `check_email_unsubscribe_token`/`confirm_email_unsubscribe`. Manual suppression only by `admin` role. Why: unsubscribe must never block transactional mail nor expose the address.
