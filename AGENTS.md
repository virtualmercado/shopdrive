- Plan codes: free|pro|premium|marca; MARCA = Premium + brand capabilities (`PLAN_LIMITS`, `get_effective_store_plan`); sale gated by `is_plan_marca_enabled()` (fail-safe false). Why: MARCA never resolves to Free.
- Lojas próprias MARCA só em `brand_account_owned_stores` (slot 1 primary, 2 secondary); herança via `get_brand_inherited_plan`. Why: uma assinatura financia 2 lojas sem autoridade de rede à secondary.
- Front MARCA (Minha Rede, checkout `plano=marca`) só lê RPCs `get_my_*`; nunca envia valor nem decide estado. Why: backend é a autoridade.
- Resolver de plano ignora `past_due` com tolerância vencida. Why: assinatura antiga esquecida mantinha plano pago.
- Estoque (simples e variação) reservado só no servidor via `reserve_order_item_stock` na criação do pedido; devolvido uma vez em cancelamento/exclusão; Entregue não move estoque. Why: baixa no navegador não era atômica.
- Regras detalhadas de backend em `supabase/AGENTS.md`.
- Catálogo PDF clássico: texto, links públicos e imagens passam por `src/lib/catalogPdfClassic.ts` (compartilhado por prévia e PDF). Why: evita divergência e vazamento do host de preview nos PDFs.

- Catálogo PDF 2.0 vive isolado em `src/lib/catalog-v2/` (loader → normalizer → CatalogDocument → `composePages` → renderer jsPDF → preview pdf.js dos mesmos bytes); `CatalogPDF.tsx` só monta `src/components/catalog/editorial/` (estado e handlers próprios, sem publicar/compartilhar). Why: paginação única e preview fiel, sem regressão do Clássico.
- Subdiretórios têm `AGENTS.md` próprio (ex.: `src/lib/catalog-v2/`); leia antes de alterar arquivos ali.
- Auth/roles state only accepts responses for the current user via `createUserScopedLoader` (`src/lib/authIdentity.ts`); lookup error never means "no store"; onboarding only writes the store address when it is still empty. Why: a delayed lookup from the previous account sent existing merchants to "Crie sua loja".
- Campaign wizard stage checks use `src/lib/emailCampaignValidation.ts`; final confirmation repeats validation server-side. Why: partial drafts must remain saveable without weakening send authorization.
- Campaign images use the existing Master MediaSelectorModal in campaign-only mode and campaignImage validators, storing only the global media reference through admin RPCs. Why: tenant media and arbitrary image URLs must never enter marketing campaigns.
- Campaign aspect-ratio advice is informational in campaignImage; responsive display widths are resolved only inside the shared server HTML renderer from existing media dimensions, with a legacy fallback for unknown dimensions. Why: preview and outgoing HTML must stay identical without transforming assets or rewriting processed history.

- Campaign management uses admin RPCs, row locks, delete guards and server-derived actions. Why: archive visibility preserves history; deletion never trusts frontend counters.
- Custom Domains V2: regras puras em `supabase/functions/_shared/customDomainCore.ts` (normalização, NS→provedor, TXT, máquina de estados); escrita só por RPCs (`claim_custom_domain`, `disconnect_custom_domain`, `admin_*`) e pela Edge `verify-custom-domain-dns` (DoH fixo); cliente não escreve em `merchant_domains`; destino DNS só de `custom_domain_platform_config`; liberação = flag global + `custom_domain_v2_access`; `resolve_public_store_by_domain` exige V2 ativo com routing+SSL. Why: fluxo V1 era simulado e qualquer navegador podia marcar SSL ativo.
- Legado VirtualMercado/VM: nunca renomear identificadores técnicos em produção; classificar (A visual / B config migrável / C estrutural) e migrar só por expand-and-contract. Why: renames quebram consumidores ativos.
